# Mirage studio page (`lucid-studio/`)

This app shows the product name Mirage (decided by the lead on 2026-11-15); it was first called Lucid Studio.

An independent React/TypeScript/Vite frontend for the team's stateful video engine.
Demo layout (2026-11-15): the page opens straight on one screen with no scrolling.
The top bar shows the Mirage logo and the original prompt.
The video fills the middle.
Below it are the command field and a particle voice orb (`src/components/ParticleOrb.tsx`) labelled "Click the orb to speak".
The intro hero, the side panel (scene memory, timing) and the captions under the video are no longer shown.

## Run

```sh
cd lucid-studio
npm ci
npm run dev -- --port 5178
```

Open http://127.0.0.1:5178. The standalone root explicitly defaults to the procedural
alpine simulator. Winter, river, night, sunset, rain and fog are composable layers.
This output is not generated by the AI video model.

```sh
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Node 22.12+ is required by the test tooling. Production output is `dist/` and the
Vite base is `./`, so it can be served at `/studio/`. On `/studio/` the application
automatically connects to the page's own origin at `/control` and `/frames`.
For local engine testing use:

```text
http://127.0.0.1:5178/?server=127.0.0.1:8000
```

The existing `?engine=` alias also works. `?server=` accepts host:port or a full
HTTP(S)/WS(S) URL. Use HTTPS/WSS for a remote engine. Speech recognition needs localhost or HTTPS,
browser support and microphone permission. Voice starts only after clicking the
agent, pressing V outside a text field, or holding backtick / Hold to talk. It stops when the editor leaves the viewport.

## Controls

- Hold the voice orb and talk (push-to-talk), or click it once to keep listening until clicked again; **V** outside a text field also toggles speech.
- Hold **backtick (`)** or **Hold to talk** for push-to-talk. Chrome segments are
  combined into one final on release. Ctrl remains available to Wispr Flow.
- Type in the prompt column; Enter sends immediately. Typing also sends after
  2.5 seconds idle; machine input uses 600 ms after four fast keys. Unfinished
  sentences ending in a comma or connector wait for Enter. Whole Wispr inserts
  and pastes send immediately. IME waits until composition ends.
- **Option/Alt+R:** reset, including while the text field has focus.
- Outside text fields, **1–5:** winter, river, night, sunset, rain. **0:** reset.
- **Ctrl/Cmd Z** or **Backspace:** undo. **/**: floating text entry.
- **Tab:** hold to peek at optical scene memory; **M:** keep it open for keyboard access.
- **?**: gestures. **Escape:** close floating views.
- Click the canvas to pin the next change. Pins expire after four seconds.
- Remove a scene-memory label with ×. Simulator sliders change that layer's intensity.

Audio FFT uses 512 samples and the requested low/vocal/sibilance bands. Typed and
simulated commands drive a synthetic voice envelope when a real mic is unavailable.

## Stream adapter

`src/types.ts` exports the requested `WorldStreamAdapter` with
`sendMutation({ prompt, activeState, spatialCoords?, timestamp }): Promise<void>`.
`App` also accepts `source: MediaStream | HTMLCanvasElement`, `remoteModifiers`,
and `initialPrompt`. A WebRTC source needs only its MediaStream passed to `source`.
With a send-only custom adapter the simulator maintains the desired composition;
with `remoteModifiers`, the caller's/server's state is authoritative.

The included websocket adapter maps final text to contract 1 and interim speech
and typed text to partial messages. Draft echoes say “hearing”; acknowledged
commands say “heard” with understood/not-understood status. Server words retain keyword highlighting and
unmatched styling; chips remain server-authoritative. Controls disable on a lost
connection, while unsent text stays editable. Connection and two-second frame-stall
notices persist until the stream recovers. It consumes contract 4 and frames with the six-byte
big-endian chunk/index header. It drops disconnected commands, reconnects with
bounded backoff, discards old decoded frames, and reads intrinsic JPEG dimensions.
It measures each correlated command once at the first frame draw; this proxy is
not a measurement of semantic change or final screen paint. The displayed server
stages are captured with that same correlated sample, never a later command.

`initialPrompt` must match a non-default backend starting prompt; contract 4 does
not currently carry the original base text. The default live copy matches the
command service's default meadow. No server files or shared contracts are changed.

## Performance

- The hero uses a one-time poster from the selected source, not a second continuous WebGL context.
- The heavy renderer loads separately from the initial UI and pauses outside the editor after the poster,
  caps its procedural target at 700,000 pixels and skips it when live texture output fully replaces it.
- Pointer movement updates a ref. FFT updates stay inside the voice agent instead
  of rerendering the editor. The particle context exists only during vocal feedback.
- Engine canvas uploads follow its frame-version marker; decoding doesn't wait for UI animation.
- Idle post-processing uses one texture lookup; shockwave aberration and local
  Sobel shimmer are temporary. Reduced motion disables continuous procedural animation.

These are implementation bounds, not a measured guarantee for every device or network.

## Remaining backend/UI boundaries

| Feature | Status |
|---|---|
| Stacking, remove-one, undo/reset, partial/final voice | Wired to existing contracts; simulator also works independently |
| Spatial coordinates | Simulator river placement responds; the websocket adapter sends only shared contract fields; the backend does not interpret spatial edits |
| Exact intensity slider | Local simulator supports it; live contract only has textual more/less commands, not an absolute slider action |
| Original prompt | Supplied by App config; needs a backend field if the starting prompt changes dynamically |
| Unknown commands | Clear feedback; a live configured LLM is owned by the command service |
| Recording/replay | No recording or replay controls added in this app |
| Real-time semantic model quality | Owned by engine/steering; the frontend does not claim the simulator demonstrates it |

The shader optics, ephemeral speech/reticle and editorial hero remain. Source
project credit stays in the editor footer. Ashima simplex noise attribution is in

## Verification

Vitest covers scene transitions, speech/input boundaries and engine protocol data.
Playwright covers desktop/short-laptop/mobile layout, shader compilation and voice
particles, Wispr/IME, push-to-talk and restart, focus, server words, disconnect and
stall recovery, correlated timing, async frame ordering and WebGL fallbacks.
Speech results and audio devices are controlled browser fixtures; real OS dictation
and actual spoken recognition still need a demo-machine check.

A local real CPU engine can be used without touching the shared GPU service:
`python -m engine.server --backend fake --reader commands --port 8100` from the repo
root, then open `?server=127.0.0.1:8100`. It renders test frames, not model video.
The optional integration test uses `LUCID_ENGINE_URL=http://127.0.0.1:8100`.

Own unsubmitted drafts remain unconfirmed until finalized or cleared, including long
thinking pauses. An edit cancels any older automatic retry of a pending paste.
Custom send-only adapters serialize successful scene edits and capture spatial
pins when submitted, so a slow response cannot erase changes or lose placement.

The CPU integration also sends a final immediately after Reset and verifies its
new correlated frame, covering the engine-owned #103 race fix.

Draft echoes correlate with their own or inherited server timestamps. Another
viewer submitting the same words is still shown as a completed command.
